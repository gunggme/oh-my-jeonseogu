# 페르소나 대화 평가

평가 목표는 같은 답을 매번 복사하는 것이 아니라, 상황이 바뀌어도 반응의 대상·크기·끝맺음이 같은 화자답게 유지되는 것이다. 짧음, 반말, 농담만으로 통과시키지 않는다. 실제 대화에서 읽은 근거와 합성 평가 입력은 구분한다.

실제 관찰은 [추가 문맥 조사](jeonseogu-context-review-2026-09-23.md), 실행할 합성 시나리오는 [반복 비교 사례](../eval/persona-cases.json)와 [추가 문맥 사례](../eval/persona-holdout.json)에 있다. 후자는 프롬프트에 직접 넣지 않은 입력이지만, 일부 상황과 평가 기준은 개발 과정에서 함께 검토했다. 독립적인 블라인드 평가 자료로 취급하지 않는다.

## 실행

기존 pi 인증을 이용하는 선택적 실모델 평가다. 모델 호출에 계정 사용량이 든다. 기본 설정은 `openai-codex/gpt-5.5`, thinking `medium`, 사례별 3회, 동시 실행 2개다.

```sh
npm run eval:persona -- \
  --provider openai-codex --model gpt-5.5 --thinking medium \
  --repeat 3 --out /tmp/jeonseogu-eval-new.jsonl
```

`--out`은 새 파일이어야 한다. 기존 결과를 덮어쓰지 않는다. 비교할 이전 페르소나는 `--persona <path>`, 일부 사례만 확인할 때는 `--ids summon,emotion`, 동시 실행 수는 `--concurrency 1`처럼 지정한다.

```sh
npm run eval:persona -- \
  --cases eval/persona-holdout.json --repeat 1 \
  --out /tmp/jeonseogu-context-new.jsonl
```

각 사례·반복은 새 메모리 세션에서 시작한다. 한 사례의 여러 턴은 같은 세션에 순서대로 넣는다. 도구, 확장, 스킬, 프로젝트 지시, 추가 시스템 지시를 제외하고, 실제 시스템 프롬프트가 지정한 페르소나와 pi의 작업 디렉터리 표시만 포함하는지 확인한다. 모델 자동 재시도와 문맥 압축도 끈다.

JSONL에는 모델·thinking·pi 버전·페르소나와 사례의 해시, 입력과 최종 답변, 사용량·소요 시간·종료 상태를 기록한다. 추론 내용과 인증 정보는 기록하지 않는다. 실행 실패와 말투의 부적합은 다르다. 종료 코드 0은 모든 응답을 받았다는 뜻이며, 스타일 평가까지 자동 통과했다는 뜻은 아니다.

실제 CLI 경로도 별도로 확인한다.

```sh
npm run build
node dist/cli.js --no-update --no-session \
  --model openai-codex/gpt-5.5 --thinking medium --print '어이 전서구.'
```

## 판단 기준

- 부름·수긍·정정 하나만으로 역할을 마쳤다면 거기서 끝나는가. 이유, 질문, 농담을 분량 때문에 추가하지 않는가.
- 장난의 전제와 중간 상대 발언을 기억하는가. 이미 확인된 사실을 다시 모른다고 하지 않는가.
- 조건을 답한 턴과 실제 구현을 요청한 턴을 구분하는가. 코드만 달라는 요청에는 코드만 주는가.
- 감정 표현에는 그 일에 반응하는가. 조언을 거절했는데 행동을 권하거나 지시를 지켰다고 보고하지 않는가.
- 자세한 설명과 구체적인 감상이 가능한가. 길어진 뒤의 잡담과 종료에서는 다시 짧아지는가.
- 실제 인물이나 없는 경험을 사칭하지 않는가. 모르는 자료를 봤다고 하지 않는가.

코드·기술 설명의 정확성, 재미, 특정 화자를 닮은 정도는 별도로 판단한다. 이 스크립트는 종합 점수나 ‘닮음 확률’을 산출하지 않는다.

### 추가 문맥 7개 사례, 13턴

최종 페르소나로 각 사례를 한 번씩 실행했다. 모든 턴의 응답을 받았으며, 실패 응답을 빼고 좋은 출력만 고른 기록이 아니다.

- 부름 → 소식 → 정정 → 종료는 `?` → `오 / 끝났다` → `아 ㅋㅋ / 잘했다` → `자라`로 반응의 크기가 바뀌었다.
- 시험을 망쳐 해결책을 원하지 않는다는 말에는 `아이고 / 그건 진짜 허탈하지`로 끝났다.
- 아직 결말을 안 봤다는 사실은 유지하고, 돌멩이인지 여부가 미정이라는 농담을 이어갔다. 다른 참여자가 끼어든 정정 장면에서는 무관한 날씨에 답하지 않았다.
- 다른 소재의 게임 감상과 자세한 기술 설명에는 긴 답변을 제공했다. 긴 설명 뒤 종료에는 `오 됐다`로 줄어들었다.

### 남은 한계

짧은 대화의 군더더기는 줄었지만 장문에서는 같은 차이를 여러 도식으로 반복하는 설명이 남는다. 기술 설명에 반말이 붙었다는 이유만으로 실제 화자를 잘 재현했다고 판정하지 않는다. 성공담에 `finally`를 섞는 등 표현 선택도 아직 흔들린다.

기술적 정확성도 완전 통과로 보지 않는다. 추가 HFSM 설명의 예시 코드에는 새 피격 입력이 없는 다음 프레임에 `Normal`로 돌아가 피격 상태의 지속 시간을 보장하지 못하는 부분이 있다. 짧은 루프 예시는 요청한 핵심 구조를 제공했지만 일부 출력은 `update`·`render`의 외부 정의를 전제한다. 조건을 정하는 턴에서 브라우저가 확정되기 전에 캔버스를 제안하는 경향도 남았다. 이 기록은 말투와 대화 차례의 개선 근거이며 생성 코드 전반의 정확성 인증이 아니다.

실제 인물의 독립적인 평가는 받지 않았고, 긴 실사용 대화와 다른 모델에서도 같은 결과가 유지되는지는 이번 표본으로 확정할 수 없다. 이후 수정에서는 특히 긴 설명의 반복과 상황별 어휘 선택을 별도로 비교한다.

### 실행 경로 검증

기본 페르소나 사용 시 빈 `--append-system-prompt`를 전달해 전역·프로젝트의 `APPEND_SYSTEM.md` 자동 유입을 차단했다. `--no-context-files`만으로는 이 파일이 차단되지 않는 것을 pi의 실제 로더로 재현했고, 기본 페르소나·별도 페르소나·명시적 추가 지시를 구분하는 테스트를 추가했다. 이 경로가 이번 사용자의 기존 응답에 실제로 영향을 주었다고 단정하지 않는다.

타입 검사, 테스트 13개, 빌드가 통과했다. 빌드한 CLI의 별도 호출에서도 `?`가 출력됐다. 평가용 SDK 경로와 실제 CLI 경로를 모두 확인한 결과다.
