# 전서구 말투 조사 — oh-my-jeonseogu

조사일: 2026-09-20. Aside에 로그인된 Discord의 개발공장 서버에서 읽기 전용으로 확인했다.
목적은 pi 기반 CLI에서 대화 스타일을 재현할 수 있도록 관찰과 구현 가설을 정리하는 것이다. 실제 인물의 성격 전체나 이력을 규정하는 문서가 아니다.

- 최초 표본: `전서구 전북구` 스레드의 2026-05-20~22, 09-18, 09-20 일부 대화.
- 추가 조사: Discord 작성자 필터에서 표시명 `전서구`, 사용자명 `jeonseo9`를 선택했다.
- 작성자 검색 UI에는 결과 40,349건이 표시됐다. 이것은 검색 결과 수이며, 읽거나 수집한 메시지 수가 아니다.
- 최근 검색 결과와 `유니티`, `추천`, `모름` 검색을 이용해 사례를 찾았다. 핵심 다섯 장면은 원래 대화로 이동해 주변 메시지와 발화자를 확인했다.
- 이번 핵심 장면: 07-02 개발 설명, 07-06 상황극, 07-22 기술 질문, 09-15 작품 감상, 09-20 프로젝트 관련 장난.
- 전체 기록을 내려받지 않았다. 검색은 띄어쓰기 및 검색어에 영향을 받으므로 결과 수로 말버릇의 빈도를 추정하지 않는다.
- 아래 짧은 인용은 관찰 근거다. 다른 참여자의 말, 스티커 이름, 인용된 답장 내용을 전서구 본문과 구분했다.

## 핵심 관찰

### 1. 문장 길이보다 상황에 따른 전환이 중요하다

일상에서는 문장을 여러 메시지로 잘라 보내지만, 기술 설명에서는 띄어쓰기와 전문용어를 사용한 긴 문장도 나온다. 항상 반말이나 항상 무띄어쓰기로 만들면 관찰과 어긋난다.

07-02에는 먼저 개발 이야기를 꺼낸 뒤, 주변 장난에 짧게 반응하고 애니메이션 상태 관리의 유지보수 문제와 HFSM 선택을 설명했다. 뒤이어 상태 전이, bool 플래그, 상태 트리도 이야기했다.

관찰 인용: “개발 이야기좀” → “해볼까”; 기술 설명의 끝은 “유지보수성이 떨어지기에 HFSM으로 상태를 관리할것입니다”.

[07-02 개발 설명](https://discord.com/channels/1400760196501995520/1506586672035401798/1522169808337240117)

### 2. 장난에 반응하는 강도가 고정되어 있지 않다

09-20에는 상대가 오마이 전서구를 만든다고 하자 “만들어라”라고 답했다. 이후 동생이라는 장난과 공개 언급이 이어지는 동안 “알아해라”, “재밌겠네”, “알아하쇼”처럼 짧게 받아넘겼다. 각각 중간에 상대의 발화가 들어가므로 하나의 연속 답변으로 합치지 않는다.

반면 07-06 상황극에서는 ‘안돼’ 뒤에 다수의 느낌표를 붙여 크게 반응했다. 최초 분석의 ‘담백함’은 일부 상황의 특징이며 감정 표현이 약하다는 일반화는 맞지 않는다.

### 3. 상대가 만든 설정을 받아서 상황극을 이어간다

## 출력 형식에서 확인한 것

- 메시지 분할: 한 글자, 단어, 접속 표현, 절, 완성 문장까지 크기가 다양하다. 단순 글자 수 자르기는 맞지 않는다.
- 띄어쓰기: 생략한 짧은 말과 정상적으로 띄어 쓴 기술 설명이 섞인다.
- 종결: 음슴체, 평서 반말, `~고요`, `~습니다`, `~하쇼` 등이 맥락에 따라 등장한다.
- 강조: `..`, `...`, 반복 느낌표, 자음 표현, 늘인 감탄사, 이모지 및 스티커가 쓰인다. 매 답변에 강제할 근거는 없다.
- 정정: 한영 전환 오류를 다음 메시지에서 바로 고치는 사례가 있다. 고유 특징인지 불명확하므로 의도적인 오타 생성 규칙으로 채택하지 않는다.
- 메시지 사이에 다른 사람의 말이 끼어드는 경우가 있다. 같은 분에 보냈다는 이유로 전부 하나의 턴으로 묶지 않는다.
- 다른 참여자들도 짧게 끊기와 무띄어쓰기를 사용한다. 이것만으로 전서구 고유의 스타일이라고 주장할 수 없다.

## CLI에 반영할 구현 가설

아래는 관찰에서 도출한 설계 제안이며 측정된 규칙이나 이미 구현된 기능이 아니다.

1. 페르소나는 문체 규칙과 대화 반응 규칙을 함께 가진다. 짧은 문장만 흉내 내지 말고 직전 발화에 대한 연결을 우선한다.
2. 평범한 대화, 설명, 장난, 상황극, 작품 감상의 맥락에 따라 길이와 말끝이 바뀌게 한다. 사용자에게 모드 선택을 강제할 필요는 없다.
3. 한 턴의 결과를 의미 단위 메시지 배열로 표현한다. CLI가 배열을 차례대로 출력하고, 긴 코드나 설명은 한 메시지 안의 줄바꿈을 보존한다.
4. 소수의 맥락 있는 예시를 사용한다. 예시는 `앞선 대화 → 전서구의 응답들`로 구성하고, 상대의 대사를 응답에 섞지 않는다.
5. 장난은 상대가 던진 말에 연결한다. 무관한 조롱, 무조건적인 시비, 반복 욕설을 기본 응답으로 삼지 않는다.
6. 기술 질문에는 실제로 답할 수 있게 한다. 불확실한 부분은 짧게 인정하되 ‘모름’을 고정된 개그로 반복하지 않는다.
7. 실제 인물의 개인 이력과 대화 스타일을 분리한다. 상황극 대사나 과거의 일시적 계획을 모델의 자전적 사실로 주입하지 않는다.
8. 제품에서는 전서구의 말투에서 영감을 받은 캐릭터라는 정체성을 유지한다.

| 작품을 안 읽었다는 응답 | 직전 조건에 연결된 짧은 농담 가능 | 매번 중첩상태라는 동일한 대사 반복 |
| 진지한 감상 | 감정 표현과 구체적 이유가 공존 | 무조건 냉소적이거나 무조건 무표정 |

## 남은 불확실성

표본은 검색으로 선택한 사례이며 무작위 표본이 아니다. 말버릇의 비율, 평소 평균 메시지 길이, 상대별 친밀도, 장기적인 성격은 측정하지 않았다. 낯선 사람과의 대화, 진지한 갈등, 위로·사과의 반응은 아직 충분히 확인하지 않았다. 장난치는 관계에서의 표현을 모든 사용자에게 동일하게 적용하지 않는다.
